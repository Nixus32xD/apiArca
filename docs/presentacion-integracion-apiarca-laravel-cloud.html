Integracion con API Fiscal ARCA/AFIP

Documentacion de presentacion para conectar una aplicacion externa de turnos/trabajos con el microservicio fiscal.

URL publica: https://apiarca-main-kf3cmx.laravel.cloud
Base API fiscal: https://apiarca-main-kf3cmx.laravel.cloud/api/fiscal
Fecha: 30/06/2026

Resumen ejecutivo: la aplicacion externa no debe integrarse directamente con ARCA/AFIP. Debe consumir esta API fiscal, que se encarga de credenciales, WSAA, WSFEv1, numeracion, CAE/CAEA, auditoria e idempotencia.

1. Estado de la API publica

Chequeo URL Resultado esperado
Aplicacion desplegada https://apiarca-main-kf3cmx.laravel.cloud Debe abrir la aplicacion Laravel.
Health check https://apiarca-main-kf3cmx.laravel.cloud/up HTTP 200.
API fiscal protegida /api/fiscal/* Sin token debe responder HTTP 401.

2. Conexion requerida

La aplicacion externa debe guardar estos valores en configuracion segura del backend. No deben quedar expuestos en JavaScript publico ni en una app cliente.

Variable Valor Descripcion
FISCAL_API_BASE_URL https://apiarca-main-kf3cmx.laravel.cloud/api/fiscal URL base para todas las llamadas fiscales.
FISCAL_API_TOKEN A definir por el propietario de la API Token interno configurado en la API. Se envia como Bearer token.
FISCAL_BUSINESS_ID Ejemplo: empresa-amigo-1 Identificador estable de la empresa fiscal dentro de la API.

Headers obligatorios

Authorization: Bearer {FISCAL_API_TOKEN}
Content-Type: application/json
X-Trace-Id: turno-123

X-Trace-Id no es obligatorio, pero se recomienda mandarlo con el ID del turno/trabajo para rastrear logs.

3. Que debe construir la aplicacion externa

Modulo / vista Objetivo Endpoint principal
Configuracion de API Fiscal Guardar URL, token y empresa fiscal. GET /companies/{company}/status
Empresa fiscal Crear o actualizar CUIT, razon social, condicion fiscal, ambiente y punto de venta. POST /companies
Credenciales ARCA Generar CSR, cargar certificado y probar credenciales. POST /companies/{company}/credentials/csr
Estado y diagnostico Ver si la empresa esta lista para facturar. GET /companies/{company}/status

4. Flujo de alta inicial

4.1 Crear o actualizar empresa fiscal

Endpoint completo:

POST https://apiarca-main-kf3cmx.laravel.cloud/api/fiscal/companies

Request:

{
  "external_business_id": "empresa-amigo-1",
  "cuit": "20123456789",
  "legal_name": "Empresa Demo",
  "fiscal_condition": "monotributo",
  "environment": "testing",
  "default_point_of_sale": 1,
  "default_voucher_type": 11,
  "enabled": true,
  "onboarding_metadata": {
    "source": "app-externa"
  }
}

Campos importantes:

  • external_business_id: identificador que luego se usara como business_id.
  • fiscal_condition: monotributo, responsable_inscripto o exento.
  • environment: testing para homologacion, production para produccion.
  • default_point_of_sale: punto de venta habilitado en ARCA.

4.2 Generar CSR para certificado ARCA

Este es el flujo recomendado porque la clave privada queda generada y guardada por la API fiscal, no por la aplicacion externa.

POST https://apiarca-main-kf3cmx.laravel.cloud/api/fiscal/companies/empresa-amigo-1/credentials/csr
{
  "key_name": "empresa-amigo-prod.key",
  "common_name": "empresa-amigo-prod",
  "organization_name": "Empresa Demo",
  "country_name": "AR"
}

La respuesta devuelve un credential.id y un csr. La aplicacion externa debe mostrar/copiar ese CSR para cargarlo en ARCA/AFIP.

4.3 Cargar certificado emitido por ARCA

PUT https://apiarca-main-kf3cmx.laravel.cloud/api/fiscal/companies/empresa-amigo-1/credentials/{credential_id}/certificate
{
  "certificate": "-----BEGIN CERTIFICATE-----\n...\n-----END CERTIFICATE-----",
  "active": true
}

La API valida que el certificado corresponda a la clave generada. Si no coincide, responde 409 certificate_private_key_mismatch.

4.4 Probar credenciales

POST https://apiarca-main-kf3cmx.laravel.cloud/api/fiscal/companies/empresa-amigo-1/credentials/test

Si responde correctamente, la empresa esta operativa para emitir comprobantes.

5. Flujo operativo: facturar al cerrar un turno

7. Generacion del PDF de factura

La API fiscal no genera el PDF comercial. La aplicacion externa debe generar el PDF usando sus datos internos y la respuesta fiscal.

Datos comerciales desde la app externa

  • Emisor: razon social, CUIT, condicion fiscal, domicilio, ingresos brutos si aplica.
  • Cliente: nombre/razon social, documento/CUIT, domicilio, condicion fiscal.
  • Turno/trabajo: fecha, descripcion del servicio, profesional/operador si aplica.
  • Items: detalle, cantidad, precio unitario, subtotal.
  • Importes: neto, IVA, tributos, exentos/no gravados, total.
  • Forma de pago, observaciones o datos operativos propios.

Datos fiscales desde la API

  • document_type y cbte_type: tipo de comprobante.
  • point_of_sale: punto de venta.
  • number: numero de comprobante.
  • authorization_code / cae: CAE autorizado.
  • cae_expires_at: vencimiento del CAE.
  • company.cuit, company.legal_name, company.fiscal_condition.

QR fiscal

El PDF deberia incluir QR fiscal cuando corresponda. La aplicacion externa puede construirlo con datos del comprobante y la respuesta fiscal.

8. Manejo de estados y errores

Estado Que significa Accion recomendada
authorizedARCA autorizo el comprobante.Guardar respuesta y generar PDF.
rejectedARCA rechazo los datos.No generar PDF fiscal. Mostrar error y corregir.
errorError local o fiscal sin autorizacion.Guardar error, mostrar mensaje y revisar diagnostico.
uncertainNo se sabe si ARCA proceso el comprobante.No emitir de nuevo. Ejecutar conciliacion.

Conciliacion y reintento seguro

POST https://apiarca-main-kf3cmx.laravel.cloud/api/fiscal/documents/{document_id}/reconcile
POST https://apiarca-main-kf3cmx.laravel.cloud/api/fiscal/documents/{document_id}/retry

Si un comprobante queda uncertain, la aplicacion externa no debe crear otro documento con otra clave. Debe usar el document_id devuelto y llamar a reconcile.

9. Consulta por turno/origen

Si la aplicacion externa pierde la respuesta o necesita reconstruir el estado fiscal del turno:

GET https://apiarca-main-kf3cmx.laravel.cloud/api/fiscal/documents/by-origin?business_id=empresa-amigo-1&origin_type=sale&origin_id=turno-123

11. Ejemplo C# / .NET

using System.Net.Http.Headers;
using System.Text;
using System.Text.Json;

var client = new HttpClient
{
    BaseAddress = new Uri("https://apiarca-main-kf3cmx.laravel.cloud/api/fiscal/")
};

client.DefaultRequestHeaders.Authorization =
    new AuthenticationHeaderValue("Bearer", fiscalApiToken);
client.DefaultRequestHeaders.Add("X-Trace-Id", "turno-123");

var payload = new
{
    business_id = "empresa-amigo-1",
    origin = new { type = "sale", id = "turno-123" },
    invoice_mode = "auto",
    concept = 2,
    point_of_sale = 1,
    customer = new
    {
        name = "Juan Perez",
        document_type = "DNI",
        document_number = "30123456",
        iva_condition = "consumidor_final"
    },
    amounts = new
    {
        imp_total = 12100,
        imp_neto = 10000,
        imp_iva = 2100,
        imp_trib = 0,
        imp_op_ex = 0,
        imp_tot_conc = 0
    },
    currency = "PES",
    currency_rate = 1,
    idempotency_key = "turno-123-factura"
};

var json = JsonSerializer.Serialize(payload);
var content = new StringContent(json, Encoding.UTF8, "application/json");
var response = await client.PostAsync("documents", content);
var body = await response.Content.ReadAsStringAsync();

if (!response.IsSuccessStatusCode)
{
    throw new Exception(body);
}

// Guardar data.id, data.status, data.number, data.cae y data.cae_expires_at.
// Generar PDF solo si data.status == "authorized".

12. Checklist de entrega para el equipo externo

  1. Guardar URL base: https://apiarca-main-kf3cmx.laravel.cloud/api/fiscal.
  2. Guardar token en backend y enviarlo como Bearer token.
  3. Crear pantalla de empresa fiscal y consumir POST /companies.
  4. Crear pantalla de credenciales con CSR, carga de certificado y test.
  5. Crear pantalla de estado fiscal y bloquear facturacion si ready=false.
  6. Al cerrar un turno, llamar a POST /documents con idempotency_key estable.
  7. Guardar la respuesta fiscal completa asociada al turno.
  8. Generar PDF solo con comprobante autorizado.
  9. Implementar consulta por origen para recuperar facturas por turno.
  10. Implementar conciliacion para estados uncertain.
Conclusion: con esta integracion, la aplicacion externa solo administra datos, consume endpoints HTTP y genera el PDF final. Toda la logica fiscal critica queda centralizada en la API desplegada en Laravel Cloud.
